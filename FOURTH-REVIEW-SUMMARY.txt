ISSUE #1: Type Safety - shouldAutoArchive
Location: src/utils/raidScheduler.ts:~47
Problem: Code does `raid.guild.autoArchive && raid.guild.archiveChannelId`
Result: Returns `string | false` instead of boolean
Better: Make it explicitly boolean with `Boolean()` wrapper or separate fields
Impact: Type confusion, potential logic errors in future
Fix: Change to `!!( raid.guild.autoArchive && raid.guild.archiveChannelId )`
     or split into two variables
Time: 5 minutes

---

ISSUE #2: Hard-coded English in getCompositionStatusText()
Location: src/utils/compositionFormatter.ts:120-140
Problem: Function takes `language` parameter but ignores it
Current: Hard-coded strings like "✅ Raid composition is ready!"
Better: Move to localization.ts and use t()
Impact: German users see English status text
Fix: Add translation keys and use getTranslations()
Time: 20 minutes

---

ISSUE #3: getArchiveStats() O(n) Memory Issue
Location: src/utils/archiveManager.ts:~355
Problem: `findMany()` loads ALL archived raids into memory, then counts
Better: Use `count()` in Prisma for totals, date-range count separately
Impact: Won't scale with large guilds (100+ raids)
Fix: Replace with database aggregation:
  - total = count({ where: {archived: true} })
  - recent = count({ where: {archived: true, archivedAt >= 30daysAgo} })
Time: 20 minutes

---

ISSUE #4: Hard-coded English Footer Message
Location: src/utils/archiveFormatter.ts:~68-73
Problem: Footer says "X archived raid(s) found" in English/German hardcoded
Better: Add translation key and use t()
Issue: Doesn't handle pluralization properly
Impact: German shows "1 archivierter Raid gefunden" (singular always)
Fix: Add 'archiveFoundCount' key to localization with plural forms
Time: 15 minutes

---

ISSUE #5: Hard-coded English in Archive Notification
Location: src/utils/archiveFormatter.ts:~100-105
Problem: Embed description says "has been moved to ..."
Better: Move to translation
Impact: Non-English users see mixed-language output
Fix: Add 'archiveMovedNotification' key and use t()
Time: 10 minutes

---

ISSUE #6: Unsafe Message Fetch in Modal Handler
Location: src/events/buttonHandler.ts:~235-245
Problem: Uses `interaction.channel?.messages.fetch(raid.messageId || '')`
Issues:
  - Fetches with empty string if messageId is null
  - Assumes modal channel == raid channel (might not be)
Better: Guard null check, use raid.channelId explicitly
Impact: Unnecessary errors, possibly wrong channel
Fix: 
  1. Guard: `if (!raid.messageId) return;`
  2. Use raid.channelId: await client.channels.fetch(raid.channelId)
  3. Then: await channel.messages.fetch(raid.messageId)
Time: 15 minutes
