ISSUE SUMMARY

FILE: src/utils/raidScheduler.ts
FUNCTION: checkAndCloseExpiredRaids()
SEVERITY: IMPORTANT (logic fix)

ISSUE: Auto-archive failure path leaves original raid message unchanged

PROBLEM:
  When archiveRaid() throws an error in checkAndCloseExpiredRaids(), the code
  has a logic flaw:
  
  1. "shouldAutoArchive" is set based on GUILD CONFIG
  2. If archiveRaid() fails, the code SKIPS the message update
  3. This is because: if (!shouldAutoArchive && raid.messageId...)
  4. Result: Original message never gets updated/cleaned up when archive fails

CURRENT BEHAVIOR:
  ```
  shouldAutoArchive = config.autoArchive && config.archiveChannelId
  if (shouldAutoArchive) {
    try {
      await archiveRaid(...) // <-- THROWS ERROR
    } catch { 
      console.error(...) 
    }
  }
  // This next block SKIPS when shouldAutoArchive=true, even on failure
  if (!shouldAutoArchive && raid.messageId && raid.channelId) {
    // Update original message
  }
  ```

EXPECTED BEHAVIOR:
  Track whether archiving actually SUCCEEDED, not just whether it was ATTEMPTED
  If archiving fails, fall back to updating the original message as if
  auto-archive was disabled

IMPACT:
  - Raid message left with buttons when it shouldn't be
  - Misleading UI state for users
  - Silent failure - raid closed but message looks active

================================================================================
SOLUTION
================================================================================

Track archiving success separately from guild config:

BEFORE:
  const shouldAutoArchive = raid.guild.autoArchive && raid.guild.archiveChannelId;
  
  if (shouldAutoArchive) {
    try {
      await archiveRaid(raid.id, raid.guildId, client);
      console.log(`✅ Auto-archived raid: ...`);
    } catch (archiveError) {
      console.error(`⚠️ Failed to auto-archive raid ${raid.id}:`, archiveError);
    }
  }
  
  if (!shouldAutoArchive && raid.messageId && raid.channelId) {
    // Update original message - SKIPPED IF ARCHIVE CONFIG IS TRUE
  }

AFTER:
  const shouldAutoArchive = raid.guild.autoArchive && raid.guild.archiveChannelId;
  let archivedSuccessfully = false;
  
  if (shouldAutoArchive) {
    try {
      await archiveRaid(raid.id, raid.guildId, client);
      archivedSuccessfully = true;
      console.log(`✅ Auto-archived raid: ...`);
    } catch (archiveError) {
      console.error(`⚠️ Failed to auto-archive raid ${raid.id}:`, archiveError);
      // archivedSuccessfully stays false, will fall back to message update
    }
  }
  
  // Update original message if archive didn't happen (or failed)
  if (!archivedSuccessfully && raid.messageId && raid.channelId) {
    // Update original message - NOW RUNS IF ARCHIVE FAILED
  }
